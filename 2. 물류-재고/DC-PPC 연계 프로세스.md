
# 1. 목적

DC(Distribution Center)와 PPC(Picking & Packing Center)의
역할 및 연계 관계를 정의한다.

DC의 상품 공급과 PPC의 주문 처리 과정에서 발생하는
재고 정보, 보충 요청, 출고 및 입고 결과의 연결 관계를 정리한다.

※ 본 문서는 공개된 B마트 물류 구조를 바탕으로 작성한
프로젝트 설계용 문서이며, 세부 시스템과 정책은 가정이다.

---

# 2. DC와 PPC의 역할 및 차이

## 2.1 DC (중앙물류기지)

- 대량 상품의 입고 및 보관
- 전체 공급 가능 재고 관리
- PPC별 상품 수요와 재고 상황을 고려한 공급 계획
- PPC로 이동할 상품의 출고 준비 및 출고 처리
- DC-PPC 간 물류 운영 및 운송 관리

## 2.2 PPC (피패킹센터)

- DC에서 공급받은 상품의 입고 검수
- PPC 내부 상품 재고 및 보관 위치 관리
- 고객 주문에 필요한 상품의 피킹 및 패킹
- 재고 부족 상품의 보충 필요 여부 파악
- 입고 오류, 재고 부족, 상품 품질 이상 등의 현장 이슈 처리

## 2.3 역할 비교

| 구분 | DC | PPC |
|---|---|---|
| 물류상 역할 | 중앙 공급 거점 | 도심형 주문 처리 거점 |
| 주요 대상 | PPC 공급 물량 | 고객 주문 상품 |
| 재고 관점 | 공급 가능한 재고 | 주문 처리 가능한 재고 |
| 주요 업무 | 보관, 공급 계획, 출고 | 입고, 진열, 피킹, 패킹 |
| 주요 연계 대상 | 여러 PPC | 담당 DC 및 고객 주문 시스템 |
| 주요 결과 | PPC로 상품 출고 | 고객 주문 상품 준비 완료 |

# 3. DC-PPC 전체 연결 구조

## 3.1 물리적 물류 흐름

공급업체
  → DC 입고 및 검수
  → DC 재고 반영
  → PPC별 공급 계획 수립
  → DC 출고 작업
  → DC에서 PPC로 상품 운송
  → PPC 입고 및 검수
  → PPC 재고 반영
  → 고객 주문 처리

## 3.2 정보 흐름

[DC 재고 관리]
  ├─ DC 가용 재고
  ├─ PPC별 출고 가능 물량
  └─ 출고 예정 정보
          ↓
[PPC 공급 계획 및 입고 관리]
  ├─ PPC별 보충 필요량
  ├─ 입고 예정 상품
  └─ 실제 입고 결과
          ↓
[재고 및 공급 정보 정합성 관리]
  ├─ DC 출고 수량
  ├─ PPC 입고 수량
  └─ 차이 발생 시 조정 및 원인 확인

※ 정보 흐름은 개념적인 구조이며, 실제 시스템의
연동 방식(API, 이벤트, 배치 등)은 별도 결정한다.

# 4. DC-PPC 연계 프로세스

## 4.1 PPC별 상품 보충 필요량 파악

1. PPC별 현재 재고를 확인한다.
2. 상품별 판매 속도 및 예상 수요를 고려한다.
3. 재고 부족 예상 상품을 식별한다.
4. 보충 대상 상품과 필요 수량을 산정한다.

**🗄️ 주요 입력 데이터:**
- PPC ID
- SKU
- 현재 재고
- 판매 가능 재고
- 입고 예정 수량
- 예상 수요
- 목표 재고 수준

**주요 결과:**
- PPC별 보충 대상 상품
- 상품별 보충 필요 수량

## 4.2 DC 공급 계획 및 출고 가능 여부 확인

1. PPC의 보충 필요량을 확인한다.
2. DC의 상품별 가용 재고를 확인한다.
3. 다른 PPC 공급 계획과 재고를 고려한다.
4. 공급 가능한 수량을 결정한다.
5. 출고 대상 및 출고 일정을 확정한다.

**예외:**
- DC 재고 부족
- 공급 가능 수량 부족
- 상품 품질 문제
- 출고 작업 지연

※ 필요 수량과 실제 공급 확정 수량은 구분한다.

## 4.3 DC 출고 처리

1. 출고 작업을 생성한다.
2. 상품별 출고 수량을 확정한다.
3. 출고 대상 상품을 준비한다.
4. 상품 및 수량을 검수한다.
5. 출고 확정 정보를 기록한다.
6. PPC 입고 예정 정보와 연결한다.

**🗄️ 주요 데이터:**
- 출고 작업 ID
- DC ID
- PPC ID
- SKU
- 출고 예정 수량
- 실제 출고 수량
- 출고 상태
- 운송 정보

## 4.4 DC에서 PPC로 운송

1. 출고 상품을 운송 차량에 적재한다.
2. 목적지 PPC와 배송 정보를 확인한다.
3. 필요한 보관 온도 및 운송 조건을 준수한다.
4. 운송 상태와 도착 결과를 기록한다.

**주요 상태 예시:**
- 출고 준비
- 출고 완료
- 운송 중
- PPC 도착

※ 위 상태 명칭은 프로젝트에서 사용할 예시다.

## 4.5 PPC 입고 및 검수

1. PPC는 입고 예정 정보를 확인한다.
2. 실제 도착 상품과 입고 예정 상품을 대조한다.
3. SKU별 실제 수량과 상품 상태를 확인한다.
4. 정상 입고 수량을 기록한다.
5. 검수 결과에 따라 PPC 재고를 반영한다.
6. 입고 결과를 DC 출고 내역과 연결한다.

예외
- 입고 수량 부족
- 입고 수량 초과
- 오배송
- 파손 및 품질 이상
- 입고 예정 정보 불일치

## 4.6 DC 출고와 PPC 입고 결과 대조

1. DC의 실제 출고 수량을 조회한다.
2. PPC의 실제 입고 수량을 조회한다.
3. 상품별 수량 차이를 비교한다.
4. 차이가 있으면 원인을 확인한다.
5. 조사 결과에 따라 재고 조정 또는 후속 처리를 수행한다.

**수량 차이 예시:**

DC 실제 출고 수량: 100개
PPC 실제 입고 수량: 98개
수량 차이: 2개

**처리 예시:**
- 운송 중 분실 여부 확인
- PPC 검수 누락 여부 확인
- 출고 및 입고 기록 확인
- 원인 확정 후 담당자 승인에 따라 조정

※ 수량 차이가 발생했다고 즉시 재고를 임의 조정하지 않는다.

# 5. DC와 PPC의 재고 관계

## 5.1 재고의 구분

- DC 재고: DC에 보관 중인 상품 재고
- PPC 재고: PPC에 보관 중인 상품 재고
- 운송 중 재고: DC에서 출고됐으나 PPC 입고가 완료되지 않은 상품
- 입고 예정 수량: PPC에 도착할 것으로 예정된 상품 수량

## 5.2 재고 이동에 따른 변화

DC 출고 확정
  → DC 재고 감소 또는 출고 대기 재고 해제
  → 운송 중 재고 반영
  → PPC 입고 확정
  → 운송 중 재고 감소
  → PPC 재고 증가

※ 재고 차감 및 증가 시점은 시스템의 재고 정책에 따라
확정한다. 출고와 입고 사이의 중복 반영을 방지해야 한다.

## 5.3 재고 정합성 원칙

- DC와 PPC의 재고를 서로 다른 보관 거점의 재고로 관리한다.
- DC 출고 예정 수량을 PPC의 실제 재고로 취급하지 않는다.
- PPC 입고 예정 수량과 실제 입고 수량을 구분한다.
- 운송 중 수량을 별도 추적할 수 있도록 한다.
- 동일 출고 건의 중복 입고 반영을 방지한다.
- 재고 조정은 사유 및 처리 이력을 남긴다.

# 6. ⚠️ 예외 및 후속 처리

| 예외 상황 | 확인 대상 | 후속 처리 |
|---|---|---|
| DC 재고 부족 | DC 가용 재고 | 공급량 조정 또는 공급 일정 변경 |
| DC 출고 지연 | 출고 작업 및 운송 일정 | PPC 공급 일정 재조정 |
| PPC 입고 수량 부족 | 출고·입고 수량 | 차이 조사 및 재고 조정 |
| 상품 파손 | 검수 결과 및 운송 이력 | 판매 가능 여부 판단 |
| PPC 재고 부족 | PPC 가용 재고 및 보충 일정 | 보충 계획 재검토 |
| 출고 정보 중복 | 출고 작업 ID | 중복 처리 방지 |
| 입고 처리 중복 | 입고 작업 ID | 중복 재고 반영 방지 |
