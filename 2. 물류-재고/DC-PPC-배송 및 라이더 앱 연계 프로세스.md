
# 1. 목적

DC, PPC, 고객 주문 시스템, 배송 관리 시스템 및 라이더 앱 간의
연계 관계와 상품 공급부터 고객 인도까지의 업무 흐름을 정의한다.

---

# 2. 시스템 및 구성 요소

## 2.1 DC (Distribution Center)

- 상품 입고 및 검수
- 중앙 재고 관리
- PPC별 상품 공급 계획 수립
- PPC 공급 상품 출고

## 2.2 PPC (Picking & Packing Center)

- DC 공급 상품 입고 및 검수
- PPC 재고 및 보관 위치 관리
- 고객 주문 상품 피킹
- 피킹 결과 검수 및 패킹
- 출고 준비 및 배송 인계

## 2.3 고객 주문 시스템

- 고객 주문 접수
- 배송지 및 배송 가능 여부 확인
- 상품 가격 및 재고 확인
- 결제 결과 반영
- 주문 취소 및 주문 상태 관리

## 2.4 배송 관리 시스템

- 배송 대상 주문 관리
- 배송 가능 여부 및 배송 작업 생성
- 라이더 배정
- 배송 진행 상태 관리
- 배송 지연 및 배송 실패 처리
- 배송 완료 결과 반영

## 2.5 라이더 앱

- 배정된 배송 작업 조회
- 배송 수락 또는 배정 결과 확인
- PPC 픽업 정보 확인
- 픽업 완료 처리
- 배송지 및 전달 요청 사항 확인
- 배송 시작 및 완료 처리
- 배송 실패 사유 등록

# 3. 전체 업무 흐름

## 3.1 상품 공급 단계

공급업체
  → DC 입고 및 검수
  → DC 재고 반영
  → PPC 공급 계획 수립
  → DC 출고
  → PPC 운송
  → PPC 입고 및 검수
  → PPC 재고 반영

## 3.2 고객 주문 및 상품 준비 단계

고객 앱
  → 주문 및 결제
  → 주문 처리 가능 여부 확인
  → 담당 PPC 결정
  → 재고 확보
  → 피킹 작업 생성
  → 상품 피킹
  → 검수 및 패킹
  → 출고 준비 완료

## 3.3 배송 단계

PPC 출고 준비 완료
  → 배송 작업 생성 또는 활성화
  → 라이더 배정
  → 라이더 앱에 배송 작업 전달
  → PPC 도착
  → 상품 및 주문 정보 확인
  → 픽업 완료
  → 배송 시작
  → 고객 배송지 도착
  → 상품 전달
  → 배송 완료 처리
  → 고객 주문 상태 갱신

# 4. DC-PPC와 배송 시스템의 연결

## 4.1 재고 공급과 고객 배송의 관계

DC는 PPC가 고객 주문을 처리할 수 있도록 상품을 공급한다.

PPC는 보유 재고를 사용해 고객 주문을 준비하고,
배송 관리 시스템은 준비된 주문을 고객에게 전달할 수 있도록
배송 작업을 관리한다.

DC는 일반적으로 고객 주문별 라스트마일 배송을 직접 처리하는
시스템이 아니라 PPC의 상품 공급을 담당하는 물류 거점으로 구분한다.

## 4.2 주요 연결 데이터

- DC ID
- PPC ID
- 주문 ID
- 주문 상품 ID
- SKU
- 재고 할당 ID
- 피킹 작업 ID
- 출고 ID
- 배송 ID
- 라이더 ID
- 픽업 확인 시각
- 배송 완료 시각

## 4.3 연결 관계

DC
  → PPC 공급 출고 ID
  → PPC 입고 ID

고객 주문
  → 담당 PPC ID
  → 피킹 작업 ID
  → 출고 ID
  → 배송 ID
  → 라이더 ID

※ 공급 출고 ID와 고객 주문 ID는 서로 다른 업무 식별자다.
DC에서 PPC로 이동한 상품과 고객에게 배송되는 상품을
같은 출고 건으로 취급하지 않는다.

# 5. 배송 작업 생성 및 라이더 배정

## 5.1 배송 작업 생성

1. 고객 주문이 배송 가능한 상태인지 확인한다.
2. 상품 준비 상태 및 담당 PPC를 확인한다.
3. 배송 작업에 필요한 주문 및 픽업 정보를 구성한다.
4. 배송 작업을 생성한다.
5. 배송 작업 상태를 관리한다.

주요 데이터
- 배송 ID
- 주문 ID
- PPC ID
- 배송지
- 배송 요청 사항
- 배송 작업 상태
- 배정된 라이더 ID

## 5.2 라이더 배정

1. 배송 가능한 라이더를 확인한다.
2. 거리, 이동 시간, 작업량 등 배정 조건을 고려한다.
3. 배송 작업을 라이더에게 배정한다.
4. 배정 결과를 배송 관리 시스템에 기록한다.
5. 라이더 앱에서 작업을 확인할 수 있도록 한다.

예외
- 배정 가능한 라이더 없음
- 라이더 배정 거절
- 라이더 응답 시간 초과
- 배정 이후 라이더 취소
- 배송 작업 중복 배정

※ 실제 배정 기준과 배정 주체는 운영 정책에 따라 결정한다.

# 6. 라이더 앱 배송 프로세스

## 6.1 배송 작업 확인

- 배정된 배송 작업 목록 조회
- 픽업 PPC 위치 확인
- 배송지 및 전달 요청 사항 확인
- 배송 작업 수락 여부 처리

## 6.2 PPC 픽업

1. 라이더가 지정된 PPC에 도착한다.
2. 배송 ID 또는 주문 정보를 확인한다.
3. PPC에서 준비한 상품과 배송 대상 정보를 대조한다.
4. 상품 인계 결과를 확인한다.
5. 픽업 완료를 처리한다.

픽업 완료 조건 예시
- 상품 준비 완료
- 배송 대상 주문 일치
- 실제 상품 인계 확인

## 6.3 배송 시작

1. 픽업 완료 여부를 확인한다.
2. 배송 시작 상태로 변경한다.
3. 배송 관리 시스템에 상태를 전달한다.
4. 고객 앱에 배송 진행 상태를 반영한다.

## 6.4 배송 완료

1. 라이더가 고객 배송지에 도착한다.
2. 배송 요청 사항에 따라 상품을 전달한다.
3. 배송 완료 처리에 필요한 정보를 등록한다.
4. 배송 관리 시스템에 완료 결과를 전달한다.
5. 고객 주문 상태를 배송 완료로 갱신한다.

배송 완료 정보 예시
- 배송 ID
- 배송 완료 시각
- 완료 처리자
- 전달 결과
- 필요한 경우 배송 완료 증빙

# 7. 주문 및 배송 상태 관리

## 7.1 주문 상태 예시

- 결제 대기
- 결제 완료
- 상품 준비 중
- 출고 준비 완료
- 배송 중
- 배송 완료
- 취소 처리 중
- 취소 완료

## 7.2 배송 작업 상태 예시

- 배정 대기
- 라이더 배정 완료
- 픽업 대기
- 픽업 완료
- 배송 중
- 배송 완료
- 배송 실패
- 배정 취소

※ 주문 상태와 배송 상태는 서로 다른 상태 체계다.
배송 상태가 변경될 때 주문 상태도 함께 갱신할 수 있지만,
두 상태를 하나의 필드로 통합하지 않는다.

# 8. 예외 처리

## 8.1 상품 준비 지연

- PPC의 상품 준비 상태 확인
- 배송 작업 활성화 가능 여부 확인
- 라이더 배정 일정 조정
- 고객 안내 필요 여부 판단

## 8.2 픽업 실패

- 상품 미준비 여부 확인
- 주문 정보 불일치 확인
- 잘못된 PPC 방문 여부 확인
- 재배정 또는 재방문 처리

## 8.3 배송 지연

- 라이더 현재 작업 상태 확인
- 배송 예정 시간 초과 여부 확인
- 고객 안내 및 운영 담당자 확인
- 필요한 경우 배송 작업 재조정

## 8.4 배송 실패

- 고객 부재
- 주소 불일치
- 고객 연락 불가
- 상품 전달 불가
- 기타 배송 불가 사유

처리 원칙
- 실패 사유 기록
- 배송 상태 갱신
- 재배송 또는 반송 필요 여부 결정
- 상품 회수 및 재고 처리 여부 결정
- 고객 안내 및 후속 처리 이력 기록

## 8.5 주문 취소와 배송의 충돌

- 상품 준비 전 취소인지 확인
- 라이더 배정 전 취소인지 확인
- 픽업 전 취소인지 확인
- 픽업 후 취소 요청인지 확인
- 배송 중 취소 요청인지 확인

처리 원칙
- 이미 완료된 업무 이력을 삭제하지 않는다.
- 현재 배송 단계에 따라 취소 가능 여부를 판단한다.
- 상품 회수, 반송, 환불 여부를 별도로 결정한다.
- 취소와 픽업 처리가 동시에 발생할 경우 중복 처리를 방지한다.

# 9. 시스템 간 데이터 연동 원칙

## 9.1 식별자 연결

- 주문 ID: 고객 주문 식별
- 출고 ID: PPC에서 주문 상품을 출고하는 작업 식별
- 배송 ID: 고객에게 전달할 배송 작업 식별
- 라이더 ID: 배송 담당자 식별

## 9.2 상태 동기화

- PPC의 상품 준비 완료 상태를 배송 시스템에 전달한다.
- 라이더 배정 결과를 배송 관리 시스템에 기록한다.
- 픽업 및 배송 진행 상태를 배송 관리 시스템에 전달한다.
- 배송 완료 결과를 주문 시스템에 반영한다.

## 9.3 중복 처리 방지

- 동일 배송 작업의 중복 생성 방지
- 동일 주문에 대한 중복 배송 배정 방지
- 픽업 완료의 중복 처리 방지
- 배송 완료의 중복 처리 방지
- 상태 변경 요청의 중복 수신에 대한 안전한 처리

## 9.4 연동 실패 처리

- 상태 전달 실패 이력 기록
- 재시도 가능 여부 판단
- 재시도 횟수 및 처리 상태 관리
- 중복 반영 방지
- 시스템 간 상태 불일치 탐지 및 복구
