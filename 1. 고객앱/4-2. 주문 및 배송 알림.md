# 1. 주문 상태 변경과 알림 발송

## 1.1 주문 상태 변경 및 알림 발송 흐름

1. **배송기사 전달완료**
   - 배송기사가 고객에게 상품을 전달한 후 라이더 앱에서 `전달완료` 처리
   - 관련 화면: 라이더 앱

2. **주문 상태 업데이트**
   - 배송완료 이벤트 `E05` 발생
   - 주문 `O9001`의 상태를 `배송완료`로 변경하고 상태 버전을 `5`로 업데이트

3. **알림 발송**
   - 주문 상태가 배송완료로 변경되면 고객에게 알림 `N05` 발송
   - 알림 `N05`는 배송완료 상태 변경 이벤트 `E05`와 연결

4. **고객 알림 수신**
   - 고객이 푸시 알림 `N05` 수신

5. **주문 상세 확인**
   - 고객이 알림을 통해 주문 상세에 진입하면 현재 주문 상태인 `배송완료`를 확인

## 1.2 중복 이벤트 및 상태 역행 방지

- **⚙️ 동일한 주문, 동일한 상태에 대한 알림은 한 번만 발송한다.**
  - 네트워크 재전송 등으로 동일 이벤트 `E05`가 중복 수신되더라도 알림 `N05`를 중복 발송하지 않는다.
  - 동일 이벤트에 대한 중복 처리를 방지한다.
- **⚙️ 이전 버전의 주문 상태 이벤트는 최신 상태를 덮어쓰지 않는다.**
  - 주문 `O9001`이 상태 버전 `5`인 배송완료 상태라면, 뒤늦게 도착한 `E04`(배송중, 버전 `4`)는 반영하지 않는다.
- **⚙️ 알림 발송 후 주문 상태가 변경되더라도 기존 알림 문구를 현재 주문 상태로 덮어쓰지 않는다.**
  - 기존 알림은 발송 당시의 상태 정보를 유지한다.
  - 알림을 눌러 진입한 주문 상세에서는 최신 주문 상태를 확인한다.

※ ❓ 결정 필요
- 알림 중복 방지 기준을 이벤트 ID로 할지, 주문 ID와 상태 코드 및 상태 버전 조합으로 할지 결정
- 알림 발송 실패 시 재시도 및 중복 발송 방지 처리 방식 결정
- 주문 상태 버전의 발급 및 비교 기준 결정

# 2. 알림 목록과 주문 상세 이동

## 2.1 알림 선택 및 주문 상세 조회

- 고객이 알림 목록에서 주문 관련 알림을 선택하면 해당 주문의 상세 페이지로 이동한다.
- 알림 문구는 발송 당시의 상태를 유지한다.
- 주문 상세에 진입하면 현재 주문 상태를 조회한다.
- **⚙️ 배송중 알림을 눌렀더라도 이미 배송이 완료된 경우 주문 상세에는 최신 상태인 배송완료를 표시한다.**
- 고객은 주문 상세에서 배송 상태를 확인할 수 있다.

예시:
- 발송 당시 알림: `배송중입니다. 주문하신 상품이 배송중입니다.`
- 알림 선택 시 실제 주문 상태: `배송완료`
- 주문 상세 표시: `배송완료`

## 2.2 알림 읽음 처리

- 고객이 알림을 선택해 주문 상세로 이동한 뒤 뒤로 돌아오면 해당 알림을 읽음 상태로 변경한다.

※ ❓ 결정 필요
- 알림 선택 즉시 읽음 처리할지, 주문 상세 진입 성공 후 읽음 처리할지 결정
- 상세 진입에 실패한 경우에도 읽음 처리할지 결정

## 2.3 ⚙️ 알림 목록 및 주문 상세 예외 처리

- 알림 목록이 비어 있는 경우 빈 목록 안내 화면을 표시한다.
- 통신 오류로 주문 상세를 조회하지 못한 경우 재시도할 수 있도록 안내한다.
- 대상 주문을 조회할 수 없는 경우 적절한 안내 메시지를 표시한다.
- 주문 상세 진입 시 현재 주문 상태를 조회할 수 있어야 한다.

※ ❓ 결정 필요
- 대상 주문을 조회할 수 없는 경우의 세부 사유별 안내 문구
- 통신 오류 시 자동 재시도 여부 및 재시도 횟수
- 주문이 취소되었거나 삭제·조회 불가 상태인 경우의 화면 처리

# 3. ✅ 로그인 및 주문 접근 권한 검증

## 3.1 로그아웃 상태에서 알림 선택

- 로그아웃 상태에서 주문 알림을 선택하면 로그인 화면으로 이동한다.
- 💬 [로그인이 필요한 서비스입니다. 주문 상세를 확인하려면 로그인해주세요.]
- 로그인 성공 후 알림에서 선택한 원래 주문의 상세 화면으로 이동한다.
- 로그인 전 선택한 주문 ID를 유지하여 원래 주문 상세로 복귀한다.

## 3.2 로그인 후 주문 접근 권한 검증

- 로그인 후 해당 주문이 현재 로그인한 계정의 주문인지 검증한다.
- 다른 계정의 주문인 경우 주문 상세를 표시하지 않는다.
- 💬 [권한이 없습니다. 다른 계정의 주문입니다.]
- 주문 소유권을 확인할 수 없는 경우에도 주문 상세 데이터에 접근할 수 없어야 한다.

※ ❓ 결정 필요
- 로그인 이후 원래 주문으로 복귀할 수 없는 경우의 처리 방식
- 주문이 존재하지 않는 경우와 다른 계정의 주문인 경우 안내 문구를 구분할지 결정
- 로그인 세션 만료 및 로그인 취소 시 복귀 처리 방식 결정

# 4. ⚙️ 푸시 수신 권한과 알림 수신 동의

## 4.1 앱 알림 동의와 OS 푸시 권한 구분

- 앱 내부의 알림 수신 동의와 운영체제(OS)의 푸시 알림 권한은 서로 별개로 관리한다.
- 앱 내부에서 알림 수신에 동의했더라도 OS 푸시 권한이 꺼져 있으면 푸시를 수신할 수 없다.
- OS 푸시 권한이 허용되어 있더라도 앱 내부의 해당 알림 수신 동의가 꺼져 있다면 해당 정책에 따라 발송 여부를 판단한다.

## 4.2 푸시 권한 거부 시 처리

- OS 푸시 권한을 거부한 경우 푸시 알림은 수신하지 않는다.
- 푸시를 수신하지 못하더라도 앱의 주문 내역에서 주문 상태를 확인할 수 있다.
- 주문 상태 조회는 푸시 수신 여부와 분리한다.

## 4.3 주문·배송 알림과 마케팅 알림 구분

- 주문·배송 알림: 주문 진행 및 배송 상태 안내
- 마케팅 알림: 프로모션, 이벤트 등 광고성 안내
- 마케팅 알림 수신 동의를 철회한 경우 마케팅 알림 발송을 중단한다.
- 주문·배송 알림은 마케팅 알림과 별도의 정책으로 관리한다.

※ ❓ 결정 필요
- 주문·배송 알림의 앱 내부 동의 및 OS 푸시 권한별 처리 기준
- 주문·배송 알림을 필수 안내로 운영할 때 푸시 외 채널을 사용할지 결정
- 마케팅 동의 철회 시 이미 예약되었거나 발송 대기 중인 알림의 처리 방식

# 5. 푸시 알림 문구 및 발송 채널 정책

## 5.1 잠금화면 알림 문구

잠금화면에 표시할 알림 문구의 상세 수준을 결정한다.

※ ❓ 결정 필요
- 상세 문구: 주문 상태 및 관련 정보를 구체적으로 표시
- 최소 문구: 개인정보 노출을 줄이도록 최소한의 정보만 표시

## 5.2 ⚙️ 알림 채널별 발송 정책

- 동일 이벤트에 대해 동일 채널의 알림이 중복 발송되지 않도록 한다.
- 앱 푸시는 동일 이벤트에 대해 한 번만 발송한다.
- SMS, 앱 푸시, 이메일 등 여러 채널을 통한 추가 안내는 별도의 정책으로 관리한다.

※ ❓ 결정 필요
- 주문·배송 알림별 사용 채널 결정
- 채널별 발송 우선순위 및 대체 발송 조건 결정
- 채널별 재시도 및 실패 처리 기준 결정
- 채널이 여러 개인 경우 각 채널의 발송 이력을 별도로 관리할지 결정

# 6. ✅ 알림 및 주문 상세 검증 시나리오

## 6.1 알림 선택 및 최신 상태 확인

- [ ] 배송중 알림 도착 후 주문 상태가 배송완료로 변경된 경우, 알림 선택 시 주문 상세에 배송완료가 표시되는지 확인
- [ ] 알림 문구가 발송 당시의 배송중 상태를 유지하는지 확인
- [ ] 주문 상세에서는 현재 주문 상태를 조회하는지 확인
- [ ] 알림 선택 후 주문 상세에서 배송완료 내용을 확인할 수 있는지 확인

## 6.2 로그인 및 접근 권한

- [ ] 로그아웃 상태에서 알림 선택 시 로그인 안내가 표시되는지 확인
- [ ] 로그인 성공 후 원래 선택한 주문 상세로 복귀하는지 확인
- [ ] 다른 계정으로 로그인한 경우 권한 오류 안내가 표시되는지 확인
- [ ] 다른 계정의 주문 상세 데이터가 노출되지 않는지 확인

## 6.3 중복 이벤트 및 주문 상태 역행

- [ ] 동일 이벤트 `E05`가 중복 수신되어도 알림 목록에 배송완료 알림이 한 건만 유지되는지 확인
- [ ] 배송완료 상태 버전 `5`가 반영된 후 이전 이벤트 `E04`(배송중, 버전 `4`)가 도착해도 주문 상태가 배송중으로 되돌아가지 않는지 확인
- [ ] 중복 이벤트 처리 후에도 주문 상세의 최신 상태가 유지되는지 확인

## 6.4 알림 목록 및 통신 오류

- [ ] 알림 선택 후 주문 상세 진입에 성공하면 뒤로 돌아왔을 때 읽음 상태가 적용되는지 확인
- [ ] 알림 목록이 비어 있는 경우 빈 목록 안내가 표시되는지 확인
- [ ] 통신 오류 시 재시도할 수 있는지 확인
- [ ] 대상 주문을 조회할 수 없는 경우 적절한 안내가 표시되는지 확인

## 6.5 푸시 권한 및 수신 동의

- [ ] OS 푸시 권한이 거부된 경우 푸시가 수신되지 않는지 확인
- [ ] 푸시 수신 여부와 무관하게 앱 주문 내역에서 주문 상태를 확인할 수 있는지 확인
- [ ] 마케팅 수신 동의를 철회한 경우 마케팅 알림 발송이 중단되는지 확인
- [ ] 주문·배송 알림과 마케팅 알림의 발송 정책이 구분되어 적용되는지 확인
