# 토스페이먼츠 결제 연동

**기획 목적:** 고객이 주문서에서 결제 수단을 선택하고 토스페이먼츠를 통해 결제할 수 있도록 한다. 결제 승인 결과에 따라 주문 상태를 갱신하며, 결제 실패·취소·통신 오류가 발생한 경우에도 주문과 결제 데이터가 일치하도록 처리한다.

## 1. 🔗 결제 흐름

주문서 작성 → 최종 주문 정보 확인 → 결제 수단 선택 → 토스페이먼츠 결제창 → 결제 인증 → 서버 결제 승인 → 주문 상태 갱신 → 결제 완료

1. **주문 정보 확인**
   - 상품, 옵션, 수량, 할인 금액, 배달팁 및 최종 결제 금액을 확인한다.
   - 재고, 구매 제한, 배송 가능 시간 등 주문 조건을 재검증한다.
2. **결제 수단 선택**
   - 고객이 토스페이먼츠를 통한 결제를 선택한다.
3. **결제 요청**
   - 서버에서 주문번호와 결제 금액을 확정하고 결제 요청에 필요한 정보를 준비한다.
4. **결제 인증**
   - 토스페이먼츠 결제창에서 고객이 결제 수단을 선택하고 결제 인증을 진행한다.
5. **결제 승인**
   - 결제 인증 결과를 서버에 전달한다.
   - 서버는 결제 승인 API를 호출하고 주문번호와 결제 금액을 검증한다.
6. **주문 상태 갱신**
   - 결제 승인 성공이 확인되면 결제 및 주문 상태를 갱신한다.
7. **결과 안내**
   - 결제 완료, 결제 실패 또는 추가 확인이 필요한 상태에 따라 적절한 화면을 표시한다.

참고: 토스페이먼츠는 결제 인증과 서버의 결제 승인 과정을 구분한다. 결제창에서 돌아왔다는 사실만으로 결제 완료 처리하지 않는다. [공식 결제 연동 가이드](https://docs.tosspayments.com/guides/v2/payment-window/integration)

## 2. 결제 데이터

### 2.1 🗄️ 주문 데이터

- 🔑 주문번호
- 🔑 주문 상품 및 수량
- 🔑 상품 금액
- 🔑 할인 금액
- 🔑 배달팁
- 🔑 최종 결제 금액
- 🔑 주문 상태

### 2.2 🗄️ 결제 데이터

- 🔑 결제코드/결제 식별 키(`paymentKey`)
- 🔑 주문번호(`orderId`)
- 🔑 결제 요청 금액(`amount`)
- 🔑 결제 수단
- 🔑 결제 상태
- 🔑 결제 승인 일시
- 🔑 취소 금액 및 취소 사유
- 🔑 결제 승인 및 취소 거래 이력

※ 결제 데이터는 주문 데이터와 연결해 관리한다. 토스페이먼츠의 `paymentKey`와 `orderId`는 결제 조회 및 후속 처리에 활용한다.

참고: [토스페이먼츠 코어 API](https://docs.tosspayments.com/reference)

---

## 3. 결제 승인 및 주문 상태 처리

### 3.1 결제 승인 성공

- 서버에서 결제 승인 결과를 확인한다.
- 주문번호와 실제 주문의 결제 금액이 일치하는지 검증한다.
- 결제 승인 성공이 확인되면 결제 상태를 완료로 변경한다.
- 주문 상태를 결제 완료 이후의 주문 처리 단계로 변경한다.
- 고객에게 결제 완료 화면과 주문 정보를 제공한다.

### 3.2 ⚠️ 결제 실패

- 결제 승인에 실패한 경우 결제 완료로 처리하지 않는다.
- 실패 원인에 따라 안내 메시지를 표시한다.
- 재결제가 가능한 경우 결제 재시도 기능을 제공한다.
- 실패한 결제 요청과 주문의 상태를 구분해 관리한다.

### 3.3 ⚠️ 결제 인증 후 결과 확인 실패

- 결제 인증 이후 서버 통신 오류 등으로 승인 결과를 확인하지 못한 경우, 결제 실패로 단정하지 않는다.
- 결제 조회 API 등을 통해 실제 결제 상태를 확인한다.
- 결과가 확인되기 전에는 동일 주문에 대한 무분별한 재결제를 방지한다.

---

## 4. 결제 취소 및 주문 취소

### 4.1 결제 취소

- 승인된 결제를 취소할 수 있도록 한다.
- 취소 요청 시 취소 사유를 기록한다.
- 취소 성공 여부를 확인한 후 결제 데이터에 취소 결과를 반영한다.
- 부분 취소를 지원할지 여부는 별도 정책으로 결정한다.

### 4.2 주문 취소와 결제 취소 연계

- 결제 전 주문 취소와 결제 완료 후 주문 취소를 구분한다.
- 결제 완료 후 주문 취소가 요청되면 주문 취소 가능 여부를 확인한다.
- 취소 가능한 주문은 결제 취소 결과에 따라 주문 및 결제 상태를 갱신한다.
- 결제 취소 요청 중 오류가 발생하면 실제 취소 여부를 확인한 후 후속 처리를 진행한다.

참고: [토스페이먼츠 결제 취소 API](https://docs.tosspayments.com/reference#%EA%B2%B0%EC%A0%9C-%EC%B7%A8%EC%86%8C)

## 5. ⚠️ 예외 처리

### 5.1 중복 결제 요청

- 동일 주문에 대한 중복 결제 요청을 방지한다.
- 중복 요청이 발생하면 기존 결제 상태를 확인한다.
- 승인 결과를 확인하지 못한 상태에서 새 결제를 무조건 생성하지 않는다.

### 5.2 결제 금액 불일치

- 서버에서 계산한 최종 결제 금액과 승인 요청 금액을 비교한다.
- 금액이 일치하지 않으면 결제 승인을 진행하지 않는다.
- 주문 금액이 변경된 경우 고객에게 변경 내용을 안내하고 재확인하도록 한다.

### 5.3 결제 승인 및 취소 통신 오류

- 요청 시간 초과 또는 응답 오류가 발생하면 결제 상태를 재확인한다.
- 실제 처리 결과를 확인하기 전에는 실패 또는 성공으로 임의 확정하지 않는다.
- 재시도 시 중복 승인 및 중복 취소가 발생하지 않도록 멱등성 처리를 고려한다.

### 5.4 보안 및 인증 정보 관리

- 시크릿 키는 서버에서만 관리한다.
- 클라이언트에는 공개용 클라이언트 키만 사용한다.
- 결제 금액은 클라이언트가 전달한 값만 신뢰하지 않고 서버의 주문 정보를 기준으로 검증한다.
- 결제 인증 결과는 서버의 승인 및 검증 절차를 거쳐 처리한다.

## 6. ✅ 검증 시나리오

- [ ] 주문서에서 토스페이먼츠 결제 수단을 선택할 수 있는지 확인
- [ ] 결제창이 정상적으로 열리는지 확인
- [ ] 결제 인증 성공 후 서버 승인 절차가 진행되는지 확인
- [ ] 결제 승인 성공 시 주문 및 결제 상태가 올바르게 갱신되는지 확인
- [ ] 결제 승인 실패 시 주문이 결제 완료 상태로 변경되지 않는지 확인
- [ ] 주문번호 또는 결제 금액이 일치하지 않으면 승인이 제한되는지 확인
- [ ] 결제 인증 후 통신 오류가 발생해도 실제 결제 결과를 확인하는지 검증
- [ ] 동일 주문의 중복 결제 요청이 방지되는지 확인
- [ ] 결제 취소 성공 및 실패 결과가 올바르게 반영되는지 확인
- [ ] 주문 취소와 결제 취소 상태가 서로 일치하는지 확인
- [ ] 시크릿 키가 클라이언트 코드나 로그에 노출되지 않는지 확인

## 7. ❓ 결정 필요 사항

- 토스페이먼츠 결제창형과 주문서형 중 적용할 연동 방식
- 지원할 결제 수단: 카드, 간편결제, 계좌이체 등
  - X
- 결제 완료 후 주문 상태 전이 기준
- 결제 인증 후 승인 결과를 확인할 수 없는 경우의 처리 방식
- 결제 재시도 허용 조건 및 기존 주문 재사용 여부
- 주문 취소 가능 시점과 결제 취소 연계 기준
- 부분 취소 지원 여부
- 결제 승인 결과 확인 및 중복 요청 방지 방식
- 결제 오류 및 취소 오류 발생 시 운영자 확인 절차
